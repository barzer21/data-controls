# ‏שימוש בכלי AI במהלך הפיתוח

## ‏חשיבה ותכנון לפני הפיתוח

‏לפני תחילת הפיתוח עם Codex, נעזרתי ב־GPT לחשיבה על הפתרון, לתכנון מפורט ולבניית הארכיטקטורה. לאחר התכנון יצרתי קובץ הוראות ודרישות, העברתי אותו ל־Codex והתחלתי את הפיתוח על בסיסו.

‏בנוסף, נעזרתי ב־AI כדי לבדוק שהפתרון נותן מענה לדרישות המטלה ולחלק את העבודה לשלבי פיתוח.

## ‏כלי הפיתוח

‏במהלך העבודה נעשה שימוש ב־OpenAI Codex דרך סביבת הפיתוח, בשיחה עם המפתחת. הכלי סייע בניתוח הקוד, הצעת מבנה ופתרונות, כתיבת קוד, בדיקות ותיעוד. המפתחת הגדירה את הדרישות, בחרה את כיוון העיצוב והנחתה את השינויים.

| ‏תחום     | ‏אופי הסיוע                                                         |
| -------- | ------------------------------------------------------------------ |
| ‏תכנון    | ‏חלוקת אחריות בין Angular, ‎.NET ו־Python; קטלוג עסקי ועץ תנאים     |
| ‏בקאנד    | ‏אימות הגדרות, תרגום ל־SQL פרמטרי, הרצה לקריאה בלבד והסברי חריגה    |
| ‏Python   | ‏בנייה הדרגתית של mock, מודלי Pydantic, בדיקת הפניות ומסלול FastAPI |
| ‏פרונטאנד | ‏מסכי RTL, עורך תנאים רקורסיבי, הצעות AI, אישור, תוצאות ומסננים     |
| ‏עיצוב    | ‏חלופות שנבדקו, דף דוגמה ב־HTML ומימוש הכיוון שנבחר עם Heebo        |
| ‏בדיקות   | ‏בדיקות Angular, בדיקות ‎.NET, תרחישי SQL ו־HTTP וסקריפט דפדפן      |
| ‏תחזוקה   | ‏איתור תקלות, הסרת קוד וקבצים זמניים, הפרדת תצוגה ולוגיקה ותיעוד    |

## ‏איך נבדק הפלט

‏הקוד עבר בנייה, בדיקות אוטומטיות ותרחישי דפדפן. חלק מבדיקות הדפדפן משתמשות בתשובות API מדומות; קיימות גם בדיקות HTTP מול שירותים אמיתיים ובדיקות SQL מול דאטה בייס או נתוני `VALUES`. חשוב להבחין בין סוגי הראיות.

‏במימוש היישום עצמו, פלט הצעות עובר אימות ב־Python ואימות עסקי נוסף ב־‎.NET. הממשק דורש אישור לפני שמירה או הרצה. SQL אינו מתקבל מה־AI.

‏אין במסמך טענה שכל הקוד נכתב ידנית או שכל בדיקה אוטומטית מחליפה סקירה והבנה של המפתחת. על המפתחת להבין את המבנה והזרימות ולהיות מסוגלת להסביר אותם.
