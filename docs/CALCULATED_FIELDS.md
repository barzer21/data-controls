# גיל כשדה עסקי מחושב

השדה `employee.age` מחושב מ־`birthDate` בזמן הרצת SQL. הוא מספרי וזמין בתנאי בקרה, בעמודות התוצאות ובמסנני התוצאות, כולל בהרצת טיוטה. אין עמודת גיל במסד ואין צורך במיגרציה.

## הגדרת הקטלוג

```json
{
  "id": "age",
  "label": "גיל",
  "column": null,
  "type": "number",
  "calculation": { "kind": "age", "sourceFieldId": "birthDate" }
}
```

`column` נשאר מאפיין מפורש בחוזה הקטלוג וערכו `null` בשדה מחושב. שדה חייב להשתמש בעמודה פיזית או בחישוב מאושר, ולא בשניהם. כרגע רק החישוב `age` נתמך. מקורו חייב להיות שדה תאריך פיזי באותה ישות; אין שרשור חישובים או SQL חופשי. מזהי שדות נפתרים ללא תלות ברישיות.

המטא־דאטה הציבורי חושף רק את המזהה `age`, התווית „גיל” והטיפוס `number`. המיפוי ומקור החישוב נשארים בשרת. חמש דוגמאות ה־AI הקיימות נשארות ללא שינוי; אין הוספת תמיכה בשפה חופשית.

## משמעות החישוב

- גיל הוא מספר שנות גיל מלאות לפי תאריך UTC בתחילת הקומפילציה של ההרצה.
- `TimeProvider` מאפשר לקבע את התאריך בבדיקות. השרת משתמש ב־`TimeProvider.System`.
- תאריך הייחוס נשלח פעם אחת כפרמטר SQL מסוג `date`, בשם `@__asOfDate`. אותו ביטוי משמש להצגה, לתנאים, למסננים ולראיות של ההסבר.
- החישוב משתמש ב־`DATEDIFF(year, ...)` ומפחית שנה כאשר יום ההולדת באותה שנה עדיין לא הגיע.
- `DATEADD` מגדיר יום הולדת של יליד 29 בפברואר כ־28 בפברואר בשנה שאינה מעוברת.
- תאריך לידה חסר או עתידי מחזיר גיל `NULL`. גיל של תינוק שנולד בתאריך הייחוס הוא `0`.
- אופרטורי מספר רגילים ובדיקות חוסר נתמכים. אין המרה של גיל חסר לאפס.
- חיפוש כללי נותר חיפוש בשדות טקסט; גיל מסונן דרך המסנן המספרי של העמודה.
- כל הרצה מחושבת מחדש להיום; אין גיל שמור בתוך הגדרת הבקרה או היסטוריית תוצאות. מסנן זמני אינו נוסף לסיבת הכישלון העסקית.

## מימוש

- `MetadataCatalog.cs`: תיאור חישוב אופציונלי בשדה.
- `MetadataValidator.cs`: אימות סוג החישוב, המקור והטיפוס.
- `SqlServerMetadataValidator.cs`: בדיקת עמודות המקור הפיזיות, בלי לדרוש עמודת גיל.
- `RuleSqlCompiler.cs`: פתרון שדה מחושב לביטוי SQL והוספת תאריך ייחוס אחד.
- `RuleResultSchema` מחזיר גם את השדה החדש, ושירות ההסברים מקבל את ערכו המחושב מה־SQL.
- Angular מקבל שדה מספרי רגיל ולכן משתמש בעורך ובמסננים הקיימים ללא הסתעפות ייעודית לגיל.

## בדיקות והרצה

משורש הפרויקט:

```powershell
dotnet run --project backend/tests/CompilerChecks -c Release -p:UseAppHost=false
dotnet run --project backend/tests/AgeChecks -c Release -p:UseAppHost=false
python -B backend/tests/check_age_api.py
```

`AgeChecks` בודק ימי הולדת, מעבר שנה, שנים מעוברות, גיל אפס, NULL ותאריכים עתידיים, מסננים והסברים. הוא מריץ את ה־SQL שהקומפיילר יצר מול `VALUES` בתוך השאילתה, ללא יצירת טבלאות או שינוי נתונים. ברירת המחדל היא חיבור Windows ל־`localhost/master`; אפשר להחליף אותו במשתנה הסביבה `AGE_TEST_CONNECTION`.

בדיקת ה־API מפעילה זמנית את גרסת Release עם תצורת Development, בודקת את המסד הקיים לקריאה בלבד וסוגרת רק את התהליך שהיא יצרה. היא דורשת עובדי דוגמה עם תאריכי לידה. בדיקת הדפדפן `frontend/tools/check-rule-workflows.mjs` כוללת מסנן גיל ותשובות דמה.

לאחר העדכון יש להפעיל מחדש את שרת ‎.NET ולרענן את הדפדפן, משום שהקטלוג נטען בהפעלת השרת ונשמר גם במטמון הממשק.
