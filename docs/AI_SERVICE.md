# שירות הצעות בקרות — מימוש הדרגתי

## הזרימה הקיימת

`POST /api/ai/proposals` בבקאנד מקבל תיאור בלבד. הבקאנד מצרף את המטא־דאטה הציבורי מהקטלוג שלו, שולח לפייתון ב־`POST /proposals`, מפענח את ההצעה כ־`RuleDefinition` ומאמת אותה ב־`RuleValidator` הקיים. רק הצעה תקינה מוחזרת ללקוח. אין שמירה ואין הרצה, ואין שינוי בנתונים עסקיים.

ממשק `IAiRuleProposalProvider` מפריד את הבקאנד ממימוש פייתון. כתובת השירות היא `AiService:BaseUrl` ב־`backend/DataControls.Api/appsettings.json`; אפשר לעקוף אותה באמצעות `AiService__BaseUrl`. זמן ההמתנה מוגבל ל־15 שניות. `CancellationToken` מעביר ביטול בקשה גם לפנייה לפייתון; ביטול מצד הלקוח אינו מסווג כ־timeout.

תיאור נדרש, באורך עד 2,000 תווים. גוף הבקשה מוגבל ל־64 KiB. מטא־דאטה שמגיע מהלקוח ושדות נוספים נדחים; רק השרת קובע את הקטלוג המועבר לפייתון. מיפויי SQL אינם נכללים בו.

## הפעלה

מהתיקייה הראשית, בטרמינל אחד:

```powershell
.\python-ai\.venv\Scripts\python.exe -m uvicorn api:app --app-dir python-ai --host 127.0.0.1 --port 8000
```

בטרמינל נוסף (נדרש SQL Server זמין לפי הגדרות הפרויקט):

```powershell
dotnet run --project backend/DataControls.Api --launch-profile http
```

אם הבקאנד כבר פועל מגרסה קודמת, עצרו אותו והפעילו מחדש כדי לטעון את ה־endpoint החדש.

דוגמאות בקשות נמצאות ב־`backend/DataControls.Api/Ai.http`. אפשר לבדוק גם באמצעות PowerShell, מתוך תיקיית הפרויקט:

```powershell
$sample = Get-Content .\python-ai\request.json -Raw -Encoding UTF8 | ConvertFrom-Json
$body = @{ description = $sample.description } | ConvertTo-Json
$proposal = Invoke-RestMethod -Uri http://localhost:5037/api/ai/proposals `
    -Method Post -ContentType 'application/json; charset=utf-8' `
    -Body ([System.Text.Encoding]::UTF8.GetBytes($body))
$proposal | ConvertTo-Json -Depth 20 | Set-Content .\python-ai\proposal.json -Encoding UTF8
```

פתחו את `python-ai/proposal.json` בעורך כדי לקרוא את הפלט בעברית. כתיבת קובץ הדוגמה בפקודה זו נעשית במחשב המקומי בלבד; ה־endpoint עצמו אינו כותב קובץ.

## תוצאות ושגיאות

| קוד | משמעות |
|---|---|
| 200 | הצעת בקרה שעברה את האימות הקיים בשרת |
| 400 | קלט חסר/שגוי, שדות בקשה לא מוכרים או תיאור שה־Mock אינו תומך בו |
| 502 | תשובת פייתון פגומה, הצעה שאינה תקינה לפי המנוע או דחיית חוזה הבקשה בשירות החיצוני |
| 503 | שירות פייתון אינו זמין או נכשל |
| 504 | יצירת ההצעה חרגה מזמן ההמתנה |

הודעות השגיאה שמוחזרות למשתמש הן בעברית. פרטים פנימיים ותוכן שגיאות של השירות החיצוני אינם מועברים ללקוח. תקלות שירות נרשמות בלוג.

## אימות

בדיקות מחלקת החיבור, ללא SQL Server או פייתון פעיל:

```powershell
dotnet run --project backend/tests/AiProposalChecks
```

בדיקת HTTP מלאה, עם שרתים זמניים ו־SQL Server זמין לקריאת קטלוג ורשימת בקרות:

```powershell
dotnet build backend/DataControls.Api/DataControls.Api.csproj --no-restore `
    -p:UseAppHost=false -o "$env:TEMP\data-controls-ai-endpoint-build"
.\python-ai\.venv\Scripts\python.exe -X utf8 backend/tests/check_ai_integration.py `
    --api-dll "$env:TEMP\data-controls-ai-endpoint-build\DataControls.Api.dll"
```

הסקריפט משתמש בפורטים פנויים, מפעיל תהליכים ללא חלונות נוספים ועוצר אותם בסיום. בשלב הראשון הוא פונה לשירות פייתון אמיתי, ובשלב השני לשירות תקלות מדומה. הוא אינו שומר או מריץ בקרות, ומשווה את רשימת הבקרות לפני ואחרי. לוגים נשמרים בתיקייה זמנית שהנתיב שלה מודפס בתחילת הבדיקה.

אימות ב־15.11.2026: הבנייה ובדיקת ה־HTTP המלאה עברו. נבדקו חמש הצעות חיות, שבע בקשות לא תקינות, תשובה פגומה, הצעה שנכשלה ב־RuleValidator, דחייה מהשירות החיצוני, שגיאת חוזה, כשל שירות, timeout ושירות כבוי. רשימת הבקרות השמורות נשארה ללא שינוי. ההרצה החיה דרשה הרשאות מורחבות בסביבה זו לצורך גישה לקריאה ל־SQL Server המקומי. בבנייה נותרו אזהרות NU1902/NU1903 על התלות הקיימת `System.Security.Cryptography.Pkcs` ‏9.0.4; לא הוחלפו חבילות במסגרת הצעד הזה.

## יצירה ואישור בממשק

הפעילו גם את Angular באמצעות `npm.cmd start` מתוך `frontend`, ופתחו `http://localhost:4200`. בסרגל הצד לחצו „יצירת בקרה בעזרת AI”. נפתח עמוד ייעודי ב־`/rules/ai/new`, ללא חלון קופץ, עם תיאור חופשי וחמש דוגמאות שניתן לבחור בלחיצה. מכיוון שזה Mock, נדרש הנוסח המדויק. בזמן הבקשה מוצג מצב טעינה, פעולת יצירה נוספת חסומה ואפשר לבטל. שגיאה שומרת את התיאור ומאפשרת ניסיון חוזר.

לאחר קבלת ההצעה, תוכן העמוד מוחלף בעורך הבקרות המשותף במצב עמוד מלא, באותו נתיב וללא dialog. מוצגים שם הבקרה וסיכום תנאי החריגה בעברית באמצעות `RuleCondition` המשותף. אפשר לערוך את כל השדות והתנאים או לדחות את ההצעה. הצעה נכנסת כטיוטה לא שמורה; עזיבה מבקשת אישור לפני ויתור עליה או על תיאור שהוזן. עזיבה בזמן יצירת ההצעה מבטלת את בקשת ה־HTTP הפעילה.

שמירה והרצה חסומות עד לסימון „בדקתי את פרטי הבקרה ואת תנאי החריגה…”. כל שינוי דרך העורך מבטל את האישור ומנקה תוצאות טיוטה קודמות. „הרצת טיוטה ללא שמירה” משתמשת באימות ובמנוע ההרצה הקיימים ומציגה תוצאות בתוך העורך. „שמירת בקרה” היא פעולה נפרדת ומחזירה לרשימה. יצירת הצעה וסימון האישור לבדם אינם שולחים בקשת שמירה או הרצה.

החיבור ל־AI נמצא ב־`AiProposalsApiService`, בנפרד משירות הבקרות. `AiRulePageComponent` מנהל את התיאור, קבלת ההצעה והעורך המשותף. העורך מקבל `initialDefinition` ללא מזהה שמור. יצירה ידנית ועריכת בקרה קיימת אינן מחייבות את תיבת אישור ה־AI. הקישור בסרגל משמר את עמוד הרשימה לצורך חזרה; שמירה מוצלחת מחזירה לעמוד האחרון ברשימה עם הודעת הצלחה ותג מקור AI.

אימות Angular ב־15.11.2026: build עבר ללא אזהרות תקציב; 69 בדיקות בשישה קבצים עברו. הבדיקות כוללות דוגמאות, שגיאות וניסיון חוזר, מניעת בקשות כפולות, ביטול בקשה עם סגירת החלון, פתיחת הצעה בעורך המשותף, חסימת שמירה/הרצה לפני אישור, ביטול האישור בעריכה, דחייה ללא בקשה והרצת טיוטה ללא שמירה. החיבור החי בין ‎.NET לפייתון נבדק בנפרד כמתועד למעלה. בדיקה חזותית וזרימה מלאה של שלושת התהליכים בדפדפן עדיין נדרשות; אין כאן טענה להשלמת QA חזותי.

מומשו AI-01..07 ו־TECH-02 ברמת הקוד והבדיקות המתועדות. ה־Mock מוגבל לחמש דוגמאות מדויקות, כמפורט ב־`python-ai/README.md`; אין חיבור למודל אמיתי. אין סימון Verified למסירה המלאה לפני בדיקת הדגמה בדפדפן.

## תיקון סגירת חלונות

ב־15.11.2026 שוחזרה ב־Edge התנהגות מבלבלת: סגירה עם שינויים הציגה את אישור הוויתור בתחתית העורך והשאירה את הפוקוס על כפתור הסגירה. בשני החלונות אישור הוויתור מוצג כעת במקום תוכן החלון, עם הסבר ברור ופוקוס על „המשך עריכה/כתיבה”. ביטול האישור שומר את הטיוטה ומחזיר פוקוס לכפתור הסגירה. Escape מבטל אישור פתוח, וסגירה ללא שינויים נשארת מיידית. חלון יצירת AI סוגר גם את ה־dialog המקורי לפני ההודעה לעמוד ההורה.

Build ו־72 בדיקות Angular עברו. `node frontend/tools/check-rule-workflows.mjs` משורש הפרויקט בודק ב־Edge headless מול build קיים ותגובות API מדומות, ללא חבילות נוספות או מסד נתונים. נבדקו חלון חדש ריק, עורך ששונה, בקרה שמורה שלא שונתה, חלון AI ריק ומלא, ביטול בקשת AI פעילה, ויתור על הצעה שנוצרה, פוקוס, Escape ותצוגה ברוחב 390 פיקסלים. צילומי המסך של אישורי הסגירה במחשב ובטלפון נבדקו חזותית. בדיקה זו מכסה את זרימות הסגירה ואינה מחליפה הדגמה חיה מלאה של שלושת השירותים בדפדפן.

## מספור ומקור יצירה

הרשימה מציגה מספור רציף לפי מיקום ברשימה, כולל המשך בין עמודים, ולא לפי מזהה המסד שעלול להכיל פערים. הצעת AI שאושרה ונשמרה נשלחת ל־`POST /api/rules?createdWithAi=true`. מקור היצירה נשמר בעמודת `CreatedWithAi`, מוחזר ברשימה ומוצג כתג קטן לצד שם הבקרה. עריכה מאוחרת אינה מסירה את התג. יצירה ידנית אינה מקבלת תג; הרצת טיוטה ללא שמירה אינה מוסיפה בקרה לרשימה.

נוספו migration ‏`AddRuleAiOrigin` וסקריפט `database/06_add_rule_ai_origin.sql`. השדרוג הוחל על מסד העבודה המקומי; 49 הבקרות הקיימות נשמרו ונשארו ללא תג, כי מקורן לא נשמר בעבר. בדיקות השמירה בוצעו במסד מבודד: 29 בדיקות עברו, כולל מקור AI ביצירה, קריאה לאחר אתחול, שימור בעריכה ונתוני הרשימה. Build של Angular והבקאנד ו־74 בדיקות Angular עברו. snapshot של EF תואם למודל ללא שינויים ממתינים.

נבדק גם ב־Edge מול תגובות API מדומות: המספרים רציפים למרות פערים במזהי הבקרות, והתג מופיע רק בבקרה שסומנה במקור כ־AI. צילומי רשימה במחשב ובמסך צר נבדקו חזותית, כולל התאמת התג לרוחב 390 פיקסלים.

## העברת יצירת AI לעמוד מלא

לפי בקשת המשתמשת, הקישור הועבר מכותרת הרשימה לסרגל הצד. גם היצירה וגם סקירת ההצעה הן עמודים רגילים בתוך מעטפת האפליקציה, ללא פתיחת dialog. הוסרו רכיב ה־AI ומצבו מעמוד הרשימה. נשמרו יצירה ידנית בחלון הקיים, עריכת בקרות שמורות בעמוד הייעודי, האישור המפורש, הרצת טיוטה ללא שמירה ותג המקור השמור.

Build ו־95 בדיקות Angular עברו. נבדקו קישור הסרגל והפריט הפעיל, פתיחת נתיב ישירה, יצירה וסקירה ללא dialog, אישור לפני הרצה, עזיבה וביטולה, ביטול בקשה פעילה, טיפול בכשל מטא־דאטה ושמירה עם מקור AI וחזרה לעמוד הרשימה האחרון. בדיקת Edge מול API מדומה עברה במחשב ובנייד; צילומי מסכי היצירה והסקירה נבדקו חזותית. לא נדרשו שינויי בקאנד או סכמה לצעד זה.
