# ‏יצירת בקרה בעזרת AI

‏שירות Python מדמה יצירת בקרה מתוך תיאור עסקי. ההצעה מוחזרת לעורך המשותף לבדיקה ולאישור המשתמש, ומשתמשת באותו מנגנון אימות, שמירה והרצה של בקרה ידנית.

‏להוראות השימוש בממשק: [הדגמת יצירת בקרה בעזרת AI](../README.md#ai-demo).

## ‏יצירת הצעה

1. ‏המשתמש מזין תיאור בעמוד `/rules/ai/new` או בוחר אחת מדוגמאות ההדגמה.
2. ‏Angular שולח את התיאור ל־`POST /api/ai/proposals` באמצעות `AiProposalsApiService`.
3. ‏הבקאנד מצרף את המטא־דאטה העסקי מהקטלוג שבשרת: ישויות, שדות, טיפוסים, קשרים ושמות להצגה. מיפויי טבלאות ועמודות SQL אינם נשלחים.
4. ‏`PythonAiRuleProposalProvider`, המממש את `IAiRuleProposalProvider`, פונה לשירות Python ב־`POST /proposals`.
5. ‏Python מחזיר הצעה לפי המודל `RuleProposal`. הבקאנד מפענח אותה כ־`RuleDefinition` ומאמת אותה באמצעות `RuleValidator`.
6. ‏הצעה תקינה מוצגת כטיוטה בעורך. יצירת ההצעה אינה שומרת בקרה ואינה מריצה אותה.

## ‏דוגמאות וחוזה הנתונים

‏חמש הדוגמאות והגדרות הבקרות שלהן מנוהלות ב־`MOCK_RULES` בקובץ `python-ai/mock_ai.py`. הרשימה `EXAMPLES` נגזרת מהן ומפורסמת ב־`GET /examples` של Python. הממשק טוען אותה דרך `GET /api/ai/proposals/examples` בבקאנד. כשל בטעינה מאפשר ניסיון חוזר בלי לאבד תיאור שהוזן.

‏ה־mock תומך בנוסחים המדויקים של הדוגמאות בלבד, לאחר הסרת רווחים בקצוות. תיאור אחר נדחה. אין חיבור למודל AI אמיתי.

‏בקשת יצירת ההצעה מהלקוח מכילה `description` בלבד, באורך עד 2,000 תווים. גוף הבקשה מוגבל ל־64 KiB. שדות לא מוכרים ומטא־דאטה שמגיע מהלקוח נדחים; הבקאנד בוחר את המטא־דאטה שנשלח ל־Python.

‏ההצעה כוללת שם, תיאור אופציונלי, מזהה ישות ראשית ועץ תנאים. התנאים תומכים בקבוצות `and` ו־`or`, בהשוואת שדה לקבוע או לשדה אחר ובכל שמונת אופרטורי המנוע. העץ מוגבל ל־100 צמתים ולעומק של 8 רמות; מסלול קשרים מוגבל ל־4 קשרים. Python בודק את מבנה ההצעה וההפניות למטא־דאטה. האימות העסקי הסופי מתבצע ב־‎.NET, כולל התאמת טיפוסי השדות והקבועים.

## ‏סקירה, אישור ושמירה

‏`AiRulePageComponent` מנהל את המעבר מטופס התיאור לסקירת ההצעה. `AiRuleCreatorComponent` מנהל את הזנת התיאור ובקשת ההצעה. לאחר קבלתה, `RuleEditorComponent` מקבל אותה דרך `initialDefinition`, ללא מזהה שמור.

- ‏אפשר לערוך את ההצעה, לעבור להצגה לקריאה בלבד או לדחות אותה.
- ‏שמירה והרצה חסומות עד לסימון אישור מפורש. שינוי בהגדרה מבטל את האישור ומנקה תוצאות טיוטה קודמות.
- ‏הרצת טיוטה היא פעולה נפרדת משמירה. היא מציגה תוצאות בעורך באמצעות רכיב התוצאות המשותף, ללא הוספת בקרה לספרייה.
- ‏שמירה שולחת את ההגדרה ל־`POST /api/rules?createdWithAi=true`. מקור היצירה נשמר בשדה `CreatedWithAi` ומוצג כתג ברשימה; עריכה מאוחרת אינה מסירה אותו.
- ‏שמירה והרצה שולחות כל אחת בקשה אחת, והשרת מאמת את ההגדרה כחלק מהפעולה. סימון האישור לבדו אינו שולח בקשה.
- ‏עזיבה עם תיאור או טיוטה שלא נשמרו מבקשת אישור. עזיבה בזמן יצירת הצעה מבטלת את הבקשה הפעילה. רענון הדפדפן מחזיר לספריית הבקרות ואינו שומר טיוטה.

## ‏תצורה וטיפול בתקלות

‏כתובת Python מוגדרת ב־`AiService:BaseUrl` בקובץ `backend/DataControls.Api/appsettings.json`, וניתנת לעקיפה באמצעות `AiService__BaseUrl`. זמן ההמתנה לפנייה מוגבל ל־15 שניות. ביטול מצד הלקוח מועבר לפנייה ל־Python ואינו מסווג כחריגה מזמן ההמתנה.

‏קודי התשובה ליצירת הצעה:

| ‏קוד | ‏משמעות |
| --- | --- |
| ‏200 | ‏הצעה שעברה אימות בשרת |
| ‏400 | ‏קלט שגוי או תיאור שאינו נתמך ב־mock |
| ‏413 | ‏גוף הבקשה חורג ממגבלת הגודל |
| ‏502 | ‏תשובה פגומה, הפרת חוזה או הצעה שנכשלה באימות |
| ‏503 | ‏שירות Python אינו זמין או נכשל |
| ‏504 | ‏חריגה מזמן ההמתנה |

‏הודעות השגיאה למשתמש הן בעברית; פרטי תקלות פנימיים נרשמים בלוג ואינם מועברים ללקוח. כשל ביצירה משאיר את התיאור ומאפשר ניסיון חוזר.

## ‏גבולות והרחבה

‏Python אינו ניגש ל־DB, אינו שומר בקרות ואינו מייצר SQL. החלפת ה־mock במודל אמיתי מתבצעת מאחורי `IAiRuleProposalProvider`, תוך שמירת חוזה ההצעה, אימות השרת ואישור המשתמש. דוגמאות לבקשות API נמצאות ב־`backend/DataControls.Api/Ai.http`; הוראות ההפעלה והבדיקה מרוכזות ב־[README הראשי](../README.md).
