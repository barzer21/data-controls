# ‏החלטות תכנון ומגבלות

‏המסמך מסביר את הבחירות המרכזיות ואת גבולות המימוש. פרטי המחלקות וזרימת הנתונים מרוכזים ב־[ארכיטקטורה](ARCHITECTURE.md), והוראות ההתקנה וההדגמה ב־[README](../README.md).

## ‏החלטות מרכזיות

### ‏הגדרת בקרה כעץ תנאים

‏נבחר עץ JSON מותאם אישית, ללא תלות ב־`System.Linq.Expressions`, במקום SQL חופשי. כך אפשר לערוך קבוצות מקוננות ולשמור אותה הגדרה עבור בקרה ידנית והצעת AI. המבנה מאפשר אימות לפני שמירה והרצה. המחיר הוא שכל אופרטור, חישוב או סוג קשר חדש דורש תמיכה מפורשת במנוע.

### ‏קטלוג עסקי מנוהל

‏השדות והקשרים המותרים מוגדרים בקובץ JSON, עם שמות עסקיים ומיפוי נפרד ל־DB. הבחירה מאפשרת שליטה במה שנחשף למשתמש וסקירת שינויים ב־Git. אין גילוי אוטומטי מלא או מסך ניהול קטלוג. שינוי דורש עדכון ידני והפעלה מחדש; שינוי מזהים או הסרת שדות עלולים לפסול בקרות קיימות. אין מנגנון להעברתן אוטומטית לגרסת קטלוג חדשה.

### ‏עץ ב־JSON ושדות סיכום בעמודות

‏העץ נשמר ב־JSON כדי לשמור קבוצות מקוננות בלי לפרק כל תנאי לטבלה. שם, סוג נתונים ופרטי סיכום נשמרים בנפרד, כדי לשלוף את הספרייה בלי לטעון את העץ. EF Core מנהל את השמירה ללא שכבת Repository כללית נוספת. גרסת ההגדרה היא גרסת פורמט; היא אינה מנגנון להגנה מעריכות מקבילות.

### ‏הפרדת שמירה מהרצה

‏הרצת טיוטה אינה משנה את הבקרה השמורה. מסלול ההרצה משתמש בחיבור נפרד ובהרשאות קריאה מוגבלות, בעוד שהחיבור הרגיל מאפשר ניהול הגדרות. כך אפשר לעדכן בקרות בלי לתת למסלול ביצוע השאילתות הרשאות שינוי. ההפרדה מחייבת הגדרת הרשאות מתאימות, ועדכון הרשאות הקריאה כשמוסיפים טבלה לקטלוג.

### ‏הסברים לפי תוצאות SQL

‏הסיבה לחריגה נגזרת מהערכים ומהתנאים שהתקיימו ב־SQL, ללא חישוב מחדש של ההשוואות ב־C#. כך נשמרת אותה משמעות גם עבור NULL, תאריכים וכללי השוואת טקסט. המחיר הוא עמודות ראיות נוספות בשאילתה ולוגיקה שמרכיבה מהן הסבר.

### ‏הצעת AI כקלט למנוע הקיים

‏שירות ההצעות מופרד ממנוע הבקרות ומחזיר את חוזה ההגדרה הקיים. הבחירה מאפשרת להחליף ספק בלי לשנות את מנגנון ההרצה. המימוש משתמש ב־Mock בהתאם להיקף המטלה. אימות מבני אינו מבטיח שהכלל נכון עסקית, ולכן ההצעה מוצגת לבדיקה ולאישור המשתמש.

## ‏כללי תאריכים, ערכים חסרים וגיל

- ‏תנאי שמתקיים מסמן חריגה. השוואות תאריך מתייחסות ליום בלבד, ללא שעה או המרת אזור זמן של הנתונים.
- ‏NULL אינו מוחלף באפס, בטקסט ריק או ב־`false`. השוואה רגילה לערך חסר אינה מסמנת חריגה; לזיהוי חוסר משתמשים ב־`isNull` או `isNotNull`.
- ‏NULL בשדה קשור עשוי להעיד על קשר חסר או על שדה חסר ברשומה קשורה קיימת. הוא אינו מבדיל לבדו בין המצבים.
- ‏גיל מחושב בשנים מלאות מתאריך לידה, במקום להישמר ולהתיישן. החישוב משתמש בתאריך UTC אחד לכל הרצה. תאריך לידה חסר או עתידי מחזיר NULL; יום ההולדת של ילידי 29 בפברואר בשנה שאינה מעוברת הוא 28 בפברואר.
- ‏השוואת טקסט נשענת על ה־`collation` של ה־DB.

## ‏מגבלות המנוע והתוצאות

- ‏לכל בקרה סוג נתונים ראשי אחד. נתמכים קשרי many-to-one עם מפתח זר יחיד ומפתח יעד ראשי יחיד. אין ניווט לאוספים, אגרגציות או תנאי „קיים עובד במחלקה”.
- ‏נתמכים מספר, טקסט, תאריך ובוליאני. השדה המחושב הנתמך הוא גיל מתוך תאריך באותה ישות. מנהל מחלקה הוא טקסט, ולא קשר לעובד.
- ‏עץ התנאים מוגבל לעומק 8 ול־100 צמתים; נתיב קשר מוגבל ל־4 קשרים. קיימות גם מגבלות אורך לקלט.
- ‏הקטלוג נבדק מול ה־DB בעליית השרת. DB לא זמין או מבנה לא תואם מונעים עלייה.
- ‏אין דפדוף בתוצאות. מגבלת הפלט ומגבלות הסינון מתוארות בארכיטקטורה. חיפוש חלקי והמרה לטקסט עלולים להכביד בנתונים גדולים; הגבלת פלט אינה מגבילה את כמות הנתונים שנסרקת.
- ‏עותק הגדרת הבקרה נשמר לאורך החיפוש והסינון, אך הנתונים אינם מוקפאים. הספירות והרשומות נקראות באותו batch ללא הבטחת snapshot טרנזאקציונלי מול עדכונים מקבילים.

## ‏מגבלות שמירה, AI ופריסה

- ‏נשמרות הגדרות בלבד: אין היסטוריית הרצות ותוצאות, תיעוד שינויים או שמירת טיוטות מתמשכת. אין הגנה מעריכות מקבילות באמצעות row version או ETag.
- ‏ניווט פנימי מבקש אישור לעזיבת טיוטה. רענון או סגירת לשונית מאבדים שינויים ללא אזהרת דפדפן. רענון מחזיר לעמוד הראשון בספרייה; קישורים ישירים וניווט רגיל נתמכים.
- ‏מחיקה דורשת אישור ומסירה רק את הגדרת הבקרה. אין מחיקה רכה או מנגנון שחזור במערכת.
- ‏ה־Mock תומך בחמישה נוסחים מדויקים לאחר הסרת רווחים בקצוות, ללא הבנת שפה חופשית. הנוסח והנקודה בסופו חשובים. אין הצעות יזומות, היסטוריית הצעות, דירוג ביטחון או ניהול עלויות מודל.
- ‏אישור AI נאכף בממשק ואינו חתימה או הרשאה בשרת. גם `CreatedWithAi` מציין מקור בלבד. חיבור מודל אמיתי דורש שמירת החוזה והאימות והוספת בדיקות איכות.
- ‏זו סביבת פיתוח ללא התחברות משתמשים, הרשאות עסקיות או הפרדה בין לקוחות. פריסה מחייבת חיבור DB והרשאות, ניתוב API ו־HTTPS. ה־proxy של Angular מיועד לפיתוח בלבד.

## ‏היקף אימות ההגשה

- ‏התקנה ובדיקות בוצעו מ־clone נקי באותו מחשב, כולל שבעת סקריפטי ההקמה ב־DB ייעודי. מחשב אחר לא נבדק.
- ‏בדיקות דפדפן מול API מדומה מכסות יצירה, עריכה, אישור AI, טיוטה, סינון, עזיבה ורענון במחשב ובמסך צר.
- ‏בנפרד נבדקו חיבור ‎.NET ל־Python פעיל, חמש ההצעות ותקלות שירות; בדיקות SQL ב־DB ייעודי מכסות הקמה, שמירה, הרצה, הסברים, סינון והרשאות. הבדיקות הנפרדות אינן הוכחה לכל תרחיש מול כל השירותים יחד.
