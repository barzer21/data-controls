# ‏בקרת נתונים — Data Controls

‏מערכת להגדרה ולהרצה של בקרות איכות נתונים, המיועדת למשתמשים עסקיים ללא ידע ב־SQL. המערכת מאפשרת ליצור, לשמור ולערוך בקרות המבוססות על תנאים וקשרים בין נתונים, ולהציג את הרשומות החריגות ואת הסיבות לחריגה. מנגנון הבקרות גנרי ומאפשר להגדיר בקרות חדשות ללא פיתוח קוד נוסף. בנוסף, המערכת מדגימה תשתית ליצירת בקרות מתיאור בשפה חופשית באמצעות שירות AI מדומה (Mock), עם אישור המשתמש לפני ההרצה.

## ‏דרישות סביבת פיתוח

‏ההוראות להלן מיועדות ל־Windows ו־PowerShell:

- ‏‎.NET 10 SDK.
- ‏Node.js בטווח `^22.22.3 || ^24.15.0 || ^26.0.0`, לפי `frontend/package.json`, ו־npm.
- ‏Python 3.13 עם אפשרות ליצור סביבה וירטואלית.
- ‏SQL Server זמין ו־SSMS או כלי להרצת סקריפטי SQL.
- ‏משתמש חיבור בעל הרשאות להקמת מבנה הדאטה בייס לצורך ההתקנה. הגדרות הפיתוח משתמשות בחיבור Windows לשרת `localhost` ולדאטה בייס `DataControlsDb`.

‏הפקודות מתבצעות משורש הפרויקט, אלא אם מצוין אחרת. אין צורך במפתח API למודל: המימוש הנוכחי הוא mock.

‏לפני התקנה מחדש של תלויות, עצרו את השירותים הפועלים באמצעות `Ctrl+C` בטרמינלים שלהם. Angular עלול לנעול קבצים ב־`node_modules`, ושירות Python פועל עלול למנוע יצירה מחדש של `.venv`.

## ‏1. הקמת הדאטה בייס

‏לדאטה בייס חדש, הריצו ב־SSMS פעם אחת ובסדר הבא:

1. ‏[01 — יצירת דאטה בייס](database/01_create_database.sql)
2. ‏[02 — טבלאות עסקיות](database/02_create_tables.sql)
3. ‏[03 — נתוני דוגמה](database/03_seed_data.sql)
4. ‏[04 — טבלת בקרות](database/04_create_rules.sql)
5. ‏[05 — משתמש בעל הרשאות קריאה מוגבלות](database/05_rule_reader.sql)
6. ‏[06 — סימון מקור AI](database/06_add_rule_ai_origin.sql)
7. ‏[07 — טעינת 10 בקרות לדוגמה](database/07_seed_rules.sql)

‏סקריפט 07 מוסיף בקרות לעובדים ולמחלקות: השוואות מספריות, טקסט ותאריכים, בדיקות ערכים חסרים, קשרים בין טבלאות וקבוצות AND/OR מקוננות. לאחר הרצתו יופיעו בספרייה 10 בקרות שאפשר לערוך ולהריץ. אפשר להריץ אותו שוב: בקרה עם אותו שם וסוג נתונים אינה נוספת ואינה נדרסת. הבקרות אינן נטענות אוטומטית בהפעלת הפרויקט ואינן מסומנות כתוצר של AI.

‏אם הדאטה בייס כבר קיים, בדקו אילו סקריפטים כבר הוחלו ואילו נדרשים להשלמת ההקמה; אין להריץ מחדש את כל סקריפטי יצירת מבנה הדאטה בייס.

‏הסקריפטים להקמת מבנה הדאטה בייס רושמים את המיגרציות בהיסטוריית EF. לחלופין, לאחר התקנת כלי EF CLI והתאמת חיבור ה־DB, אפשר להריץ משורש הפרויקט `dotnet ef database update --project backend/DataControls.Api -- --environment Development`. אין להחיל את אותן מיגרציות בשני המסלולים. נתוני הדוגמה, הרשאות הקריאה והבקרות לדוגמה עדיין דורשים את סקריפטים 03, 05 ו־07. כלי EF CLI נדרש רק למסלול החלופי ואינו מותקן אוטומטית בהוראות האלה.

‏משתמש החיבור של השרת צריך הרשאות CRUD לבקרות ויכולת `IMPERSONATE` על `DataControlsRuleReader`. סקריפט 05 מגדיר את משתמש הקריאה והרשאותיו, ואינו מעניק אוטומטית הרשאת impersonation למשתמש חיבור חדש של היישום.

‏בדקו את `backend/DataControls.Api/appsettings.Development.json` והתאימו את החיבור לסביבה שלכם. אפשר לעקוף אותו דרך `ConnectionStrings__DefaultConnection`. אין לשמור סיסמאות ב־Git.

## ‏2. התקנת תלויות

<div dir="ltr">

```powershell
dotnet restore backend/DataControls.slnx

npm.cmd --prefix frontend ci

python -m venv python-ai/.venv
.\python-ai\.venv\Scripts\python.exe -m pip install -r python-ai/requirements.txt
```

</div>

‏`npm.cmd` משמש כדי להימנע מחסימת `npm.ps1` בחלק מהגדרות PowerShell. אין צורך להפעיל את סביבת Python ב־Activate; אפשר לפנות ישירות למפרש שבתוכה.

## ‏3. הפעלה בשלושה טרמינלים

‏בטרמינל הראשון — שירות Python:

<div dir="ltr">

```powershell
.\python-ai\.venv\Scripts\python.exe -m uvicorn api:app --app-dir python-ai --host 127.0.0.1 --port 8000
```

</div>

‏בטרמינל השני — בקאנד:

<div dir="ltr">

```powershell
dotnet run --project backend/DataControls.Api --launch-profile http
```

</div>

‏בטרמינל השלישי — Angular:

<div dir="ltr">

```powershell
npm.cmd --prefix frontend start
```

</div>

‏פתחו [את הממשק המקומי](http://localhost:4200).

| ‏שירות | ‏כתובת |
| --- | --- |
| ‏Angular | ‏`http://localhost:4200` |
| ‏מטא־דאטה של ה־API | ‏`http://localhost:5037/api/metadata` |
| ‏תיעוד FastAPI מקומי | ‏`http://127.0.0.1:8000/docs` |

‏ה־proxy בקובץ `frontend/proxy.conf.json` מעביר בקשות `/api` לבקאנד בפורט 5037. שינויו דורש הפעלה מחדש של Angular. כתובת Python מוגדרת ב־`AiService:BaseUrl` וניתנת לעקיפה באמצעות `AiService__BaseUrl`.

‏הבקאנד בודק את הקטלוג מול מבנה הדאטה בייס בעת העלייה. דאטה בייס לא זמין או מיפוי לא תקין מונעים עלייה. שינוי ב־`metadata.json` דורש הפעלה מחדש של הבקאנד ורענון הדפדפן.

## ‏שימוש במערכת

- ‏ספריית הבקרות: דפדוף, מספור רציף, תג מקור AI, עריכה, מחיקה והרצה. מחיקה דורשת אישור ואינה ניתנת לשחזור.
- ‏יצירת בקרה חדשה: בחירת נתונים בכרטיסים, תנאי AND/OR, שדות קשורים, שם ותיאור.
- ‏עריכה והצגה: מעבר בין טופס לבין הגדרה לקריאה בלבד בלי לאבד את הטיוטה.
- ‏שמירה: אימות, יצירה או עדכון, ואז חזרה לספרייה עם הודעת הצלחה.
- ‏הרצה: אינה שומרת את הטיוטה. התוצאות כוללות חריגות תואמות מתוך כלל רשומות הישות, ערכים וסיבות לחריגה.
- ‏חיפוש וסינון: חיפוש חלקי בטקסט, מספרים, תאריכים וערכי כן/לא בשדות המוצגים, כולל גיל מחושב. מסנני עמודה מאפשרים תנאים מדויקים. הפעולות מתבצעות בשרת ואינן משנות את הבקרה.
- ‏יצירת AI: בחירה באחת מחמש הדוגמאות הנתמכות, קבלת הצעה ואישור מפורש לפני שמירה או הרצה. שינוי בהצעה מאפס את האישור.

‏גיל מחושב בשנים מלאות מתאריך הלידה לפי תאריך UTC של ההרצה. המדיניות לתאריכים חסרים, עתידיים ו־29 בפברואר מפורטת ב־[החלטות ומגבלות](docs/DESIGN_AND_LIMITATIONS.md).

‏בקלט מספרי יש להשתמש בנקודה עשרונית, ללא פסיקים או כתיב מעריכי.

## AI Demo

‏**הדגמת יצירת בקרה בעזרת AI**

1. ‏הפעילו את שלושת השירותים לפי ההוראות לעיל, ופתחו את הממשק.
2. ‏בסרגל הצד לחצו על „יצירת בקרה בעזרת AI”. בעמוד שנפתח, לחצו על אחת מחמש הדוגמאות כדי למלא את תיאור הבקרה, ואז על „יצירת הצעה לבדיקה”. ה־mock מקבל את הנוסחים המדויקים שמופיעים בדוגמאות.
3. ‏בדקו את השם, התיאור והתנאים שהוחזרו. לפני אישור ההצעה, כפתורי השמירה וההרצה מושבתים.
4. ‏סמנו את אישור ההצעה והפעילו „הרצת טיוטה ללא שמירה”. יוצגו מספר החריגות, הרשומות והסיבות לחריגה.
5. ‏שמרו את הבקרה, חזרו לספרייה והפעילו אותה משם. אפשר גם לערוך ולשמור אותה מחדש.

‏התהליך משתמש בשירות Python המקומי ובאותו מנוע בקרות המשמש ליצירה ידנית, ללא פנייה למודל AI חיצוני. את הדוגמאות הנוספות ב־[מסמך הבקרות](docs/EXAMPLE_RULES.md) אפשר להגדיר ידנית או להריץ דרך ה־API; הן אינן בהכרח נוסחים שה־mock מקבל.

| ‏נושא | ‏מסמך |

‏לבדיקה ישירה של Python אפשר לפתוח את `http://127.0.0.1:8000/docs`, לבחור `POST /proposals` ולהעביר את כל תוכן `python-ai/request.json`, הכולל תיאור ומטא־דאטה. לחלופין, לאחר התקנת התלויות, הפקודה הבאה קוראת את אותו קובץ ושומרת את ההצעה ב־`python-ai/proposal.json`, ללא שמירה ב־DB:

<div dir="ltr">

```powershell
.\python-ai\.venv\Scripts\python.exe -X utf8 python-ai/main.py
```

</div>

‏קובץ הפלט עשוי להישאר מהרצה קודמת אם הקלט שגוי; יש לבדוק שהפקודה הסתיימה בהצלחה. רשימת הנוסחים הנתמכים זמינה ב־`GET /api/ai/proposals/examples` בבקאנד.
