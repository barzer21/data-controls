# בקרת נתונים — Data Controls

יישום בעברית וב־RTL להגדרת בקרות עסקיות, שמירה והרצה על נתוני SQL Server. הבקרות נבנות כתנאים מקוננים ללא SQL, והתוצאות כוללות סיבות לחריגה, חיפוש וסינון. שירות Python מספק הצעות דמה שדורשות בדיקה ואישור בממשק.

## דרישות סביבת פיתוח

ההוראות להלן מיועדות ל־Windows ו־PowerShell:

- ‎.NET 10 SDK.
- Node.js בטווח `^22.22.3 || ^24.15.0 || ^26.0.0`, לפי `frontend/package.json`, ו־npm.
- Python 3.13 עם אפשרות ליצור סביבה וירטואלית.
- SQL Server זמין ו־SSMS או כלי להרצת סקריפטי SQL.
- משתמש חיבור בעל הרשאות להקמת מבנה הדאטה בייס לצורך ההתקנה. הגדרות הפיתוח משתמשות בחיבור Windows לשרת `localhost` ולדאטה בייס `DataControlsDb`.

הפקודות מתבצעות משורש הפרויקט, אלא אם מצוין אחרת. אין צורך במפתח API למודל: המימוש הנוכחי הוא mock.

לפני התקנה מחדש של תלויות, עצרו את השירותים הפועלים באמצעות `Ctrl+C` בטרמינלים שלהם. Angular עלול לנעול קבצים ב־`node_modules`, ושירות Python פועל עלול למנוע יצירה מחדש של `.venv`.

## 1. הקמת הדאטה בייס

לדאטה בייס חדש, הריצו ב־SSMS פעם אחת ובסדר הבא:

1. [01 — יצירת דאטה בייס](database/01_create_database.sql)
2. [02 — טבלאות עסקיות](database/02_create_tables.sql)
3. [03 — נתוני דוגמה](database/03_seed_data.sql)
4. [04 — טבלת בקרות](database/04_create_rules.sql)
5. [05 — משתמש בעל הרשאות קריאה מוגבלות](database/05_rule_reader.sql)
6. [06 — סימון מקור AI](database/06_add_rule_ai_origin.sql)

בדאטה בייס קיים שכבר הוקם בגרסה הקודמת, יש לבדוק אילו שדרוגים חסרים; אין להריץ מחדש את כל סקריפטי יצירת מבנה הדאטה בייס. הוספת גיל וספירת הרשומות אינה דורשת מיגרציה.

הסקריפטים להקמת מבנה הדאטה בייס רושמים את המיגרציות בהיסטוריית EF. אפשר לבחור במקום זאת במסלול `dotnet ef database update`, אך אין להחיל את אותן מיגרציות בשני המסלולים. נתוני הדוגמה והרשאות הקריאה עדיין דורשים את סקריפטים 03 ו־05. כלי EF CLI נדרש רק למסלול החלופי ואינו מותקן אוטומטית בהוראות האלה.

משתמש החיבור של השרת צריך הרשאות CRUD לבקרות ויכולת `IMPERSONATE` על `DataControlsRuleReader`. סקריפט 05 מגדיר את משתמש הקריאה והרשאותיו, ואינו מעניק אוטומטית הרשאת impersonation למשתמש חיבור חדש של היישום.

בדקו את `backend/DataControls.Api/appsettings.Development.json` והתאימו את החיבור לסביבה שלכם. אפשר לעקוף אותו דרך `ConnectionStrings__DefaultConnection`. אין לשמור סיסמאות ב־Git.

## 2. התקנת תלויות

```powershell
dotnet restore backend/DataControls.slnx

npm.cmd --prefix frontend ci

python -m venv python-ai/.venv
.\python-ai\.venv\Scripts\python.exe -m pip install -r python-ai/requirements.txt
```

`npm.cmd` משמש כדי להימנע מחסימת `npm.ps1` בחלק מהגדרות PowerShell. אין צורך להפעיל את סביבת Python ב־Activate; אפשר לפנות ישירות למפרש שבתוכה.

## 3. הפעלה בשלושה טרמינלים

בטרמינל הראשון — שירות Python:

```powershell
.\python-ai\.venv\Scripts\python.exe -m uvicorn api:app --app-dir python-ai --host 127.0.0.1 --port 8000
```

בטרמינל השני — בקאנד:

```powershell
dotnet run --project backend/DataControls.Api --launch-profile http
```

בטרמינל השלישי — Angular:

```powershell
npm.cmd --prefix frontend start
```

פתחו [את הממשק המקומי](http://localhost:4200).

| שירות | כתובת |
| --- | --- |
| Angular | `http://localhost:4200` |
| מטא־דאטה של ה־API | `http://localhost:5037/api/metadata` |
| תיעוד FastAPI מקומי | `http://127.0.0.1:8000/docs` |

ה־proxy בקובץ `frontend/proxy.conf.json` מעביר בקשות `/api` לבקאנד בפורט 5037. שינויו דורש הפעלה מחדש של Angular. כתובת Python מוגדרת ב־`AiService:BaseUrl` וניתנת לעקיפה באמצעות `AiService__BaseUrl`.

הבקאנד בודק את הקטלוג מול מבנה הדאטה בייס בעת העלייה. דאטה בייס לא זמין או מיפוי לא תקין מונעים עלייה. שינוי ב־`metadata.json` דורש הפעלה מחדש של הבקאנד ורענון הדפדפן.

## שימוש במערכת

- ספריית הבקרות: דפדוף, מספור רציף, תג מקור AI, עריכה והרצה.
- יצירת בקרה חדשה: בחירת נתונים בכרטיסים, תנאי AND/OR, שדות קשורים, שם ותיאור.
- עריכה והצגה: מעבר בין טופס לבין הגדרה לקריאה בלבד בלי לאבד את הטיוטה.
- שמירה: אימות, יצירה או עדכון, ואז חזרה לספרייה עם הודעת הצלחה.
- הרצה: אינה שומרת את הטיוטה. התוצאות כוללות חריגות תואמות מתוך כלל רשומות הישות, ערכים וסיבות לחריגה.
- סינון: לפי שדות מוצגים, כולל גיל מחושב. חיפוש כללי מיועד לשדות טקסט. הסינון מתבצע בשרת ואינו משנה את הבקרה.
- יצירת AI: בחירה באחת מחמש הדוגמאות הנתמכות, קבלת הצעה ואישור מפורש לפני שמירה או הרצה. שינוי בהצעה מאפס את האישור.

גיל מחושב בשנים מלאות מתאריך הלידה לפי תאריך UTC של ההרצה. המדיניות לתאריכים חסרים, עתידיים ו־29 בפברואר מפורטת ב־[החלטות ומגבלות](DECISIONS.md).

## הדגמת שלב ב׳ באמצעות mock

1. הפעילו את שלושת השירותים לפי ההוראות לעיל, ופתחו את הממשק.
2. בחרו „יצירת בקרה בעזרת AI”, לחצו על אחת מחמש הדוגמאות ואז על „יצירת הצעה לבדיקה”. יש להשתמש בנוסח הנתמך שמופיע בכפתור הדוגמה.
3. בדקו את השם, התיאור והתנאים שהוחזרו. לפני אישור ההצעה, כפתורי השמירה וההרצה מושבתים.
4. סמנו את אישור ההצעה והפעילו „הרצת טיוטה ללא שמירה”. יוצגו מספר החריגות, הרשומות והסיבות לחריגה.
5. שמרו את הבקרה, חזרו לספרייה והפעילו אותה משם. אפשר גם לערוך ולשמור אותה מחדש.

התהליך משתמש בשירות Python המקומי ובאותו מנוע בקרות המשמש ליצירה ידנית, ללא פנייה למודל AI חיצוני. את הדוגמאות הנוספות ב־[מסמך הבקרות](docs/EXAMPLE_RULES.md) אפשר להגדיר ידנית או להריץ דרך ה־API; הן אינן בהכרח נוסחים שה־mock מקבל.

## בנייה ובדיקות

```powershell
dotnet build backend/DataControls.slnx -c Release
dotnet run --project backend/tests/CompilerChecks -c Release -p:UseAppHost=false
dotnet run --project backend/tests/AgeChecks -c Release -p:UseAppHost=false

npm.cmd --prefix frontend run build
npm.cmd --prefix frontend test -- --watch=false
```

בדיקות הקומפיילר אינן מריצות SQL. בדיקות הגיל מריצות SQL לקריאה בלבד מול נתוני VALUES, ודורשות SQL Server; הן אינן יוצרות טבלאות ואינן משנות נתונים.

בדיקות נוספות והדרישות שלהן:

- `frontend/tools/check-rule-workflows.mjs`: בדיקות דפדפן מול build ותגובות API מדומות. דורש Edge מותקן, או כתובת לדפדפן מתאים במשתנה `BROWSER_TEST_EXECUTABLE`.
- `backend/tests/check_age_api.py`: API זמני מול דאטה בייס הפיתוח, לקריאה בלבד; דורש build של Release ונתוני דוגמה.
- `backend/tests/Test-RulePersistence.ps1`: יוצר דאטה בייס בדיקה נפרד.
- בדיקות שירות Python והחיבור אליו: [AI_SERVICE](docs/AI_SERVICE.md).

## אימות הגשה — 16.11.2026

התוצרים נבדקו מול מסמך המטלה המקורי. קיימים קוד המקור, ששת סקריפטי ה־DB, הוראות ההתקנה, מסמך הארכיטקטורה, דוגמאות הבקרות, תהליך הדגמת mock, הנחות ומגבלות וגילוי השימוש בכלי AI.

- לאחר גיבוי ה־DB הקודם, `DataControlsDb` נמחק ונוצר מחדש באמצעות הסקריפטים 01–06 לפי הסדר. התקבלו 20 עובדים, 5 מחלקות וטבלת `Rules` ריקה, וכן שלוש רשומות בהיסטוריית המיגרציות.
- פקודות שחזור ובניית ‎.NET, התקנה מחדש של תלויות Angular והתקנת דרישות Python בסביבה וירטואלית חדשה עברו. שלושת השירותים עלו באמצעות פקודות ההפעלה שבמסמך.
- עברו 115 בדיקות Angular, 49 בדיקות קומפיילר, 55 בדיקות גיל ו־99 בדיקות שמירה, הרצה, הסברים, סינון והרשאות SQL ב־DB בדיקה נפרד. עברו גם בדיקות API לגיל ולספירות ובדיקות חיבור ‎.NET ל־Python, כולל שגיאות שירות.
- בדיקת Edge מול Angular, ‎.NET, Python וה־DB האמיתיים כיסתה הצעה ואישור, הרצת טיוטה, שמירה, עריכה, הרצה מהספרייה, ספירות, סיבות לחריגה וחיפוש. נבדקה גם תצוגת תוצאות ברוחב 390 פיקסלים. בקרת הבדיקה נמחקה בסיום. בדיקות הדפדפן עם תשובות API מדומות עברו בנפרד.
- כל חמש דוגמאות ה־JSON עברו אימות והרצה מול ה־DB החדש. פרטי עובד חסרים נבדקים לפי תאריך תחילת העסקה או שיוך למחלקה, כדי להדגים חוסרים הקיימים בנתוני הדוגמה.

האימות נעשה בסביבת העבודה הקיימת עם DB חדש, התקנת Angular מחדש וסביבת Python חדשה; לא בוצע clone חדש או מבחן התקנה במחשב אחר. בבניית ‎.NET נותרו אזהרות NuGet ברמות moderate ו־high על התלות העקיפה `System.Security.Cryptography.Pkcs` בגרסה 9.0.4. הן לא מנעו בנייה והרצה, אך דורשות טיפול נפרד לפני שימוש בייצור.

## מגבלות והגשה

אין כרגע מודל AI אמיתי, התחברות משתמשים, דפדוף תוצאות מלא, היסטוריית הרצות או זיהוי התנגשויות בעריכה. מחיקה קיימת ב־API בלבד. רענון או סגירת לשונית מאבדים טיוטה שלא נשמרה.

המסמך [החלטות ומגבלות](DECISIONS.md) ומסמך [מעקב הדרישות](REQUIREMENTS.md) מפרטים את מה שנותר לבדוק לקראת הגשה. קיום מסמך או בדיקה עם תשובות מדומות אינו מחליף הדגמה חיה של כל השירותים יחד.
