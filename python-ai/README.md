# רכיב Python — לימוד ומימוש הדרגתי

`mock_ai.py` מכיל פונקציה `propose_rule(description, metadata)` המקבלת תיאור ומטא־דאטה עסקי ומחזירה מילון עם הצעת בקרה. זו הדמיה לימודית עם חמש בקשות מוגדרות בלבד, ולא תמיכה בשפה חופשית או חיבור למודל AI. השירות מחובר ל־Angular דרך שרת ‎.NET, שמספק את המטא־דאטה ומאמת את ההצעה. המשתמש מאשר את ההצעה לפני שמירה או הרצה; Python עצמו אינו שומר ואינו מריץ בקרות. אפשר להשתמש גם ב־`main.py` וב־`request.json` ללימוד ולבדיקה דרך קבצים.

הנוסחים הנתמכים (התאמה מדויקת, כולל הנקודה בסוף; רווחים בקצוות מוסרים):

- `מצאי עובדים שתאריך סיום ההעסקה שלהם מוקדם מתאריך תחילת ההעסקה.` — השוואת `endDate` לשדה `startDate` באמצעות `lessThan`.
- `מצאי עובדים שהשכר שלהם גבוה מ-15000.` — השוואת `salary` לערך המספרי הקבוע `15000` באמצעות `greaterThan`.
- `מצאי עובדים פעילים שהשכר שלהם גבוה מ-15000.` — קבוצת `and`: השדה `isActive` שווה ל־`true`, וגם `salary` גדול מ־`15000`.
- `מצאי עובדים פעילים שהמחלקה שלהם לא פעילה.` — קבוצת `and`: העובד פעיל וגם שדה `isActive` של המחלקה המשויכת שווה ל־`false`, דרך הקשר `employeeDepartment`.
- `מצאי עובדים שחסר להם שם פרטי או שכר.` — קבוצת `or` עם `isNull` על `firstName` ועל `salary`, ללא צד ימין. חוסר הוא NULL, ולא אפס או טקסט ריק.

כל נוסח אחר מחזיר שגיאה מפורשת. כך לא מוחזרת בקרה שאינה תואמת לבקשה.

`main.py` מייבא את הפונקציה מתוך `mock_ai`, ומטפל בקריאת הקובץ, בהצגת שגיאות ובשמירת הפלט. `mock_ai.py` אינו קורא או כותב קבצים ואינו מדפיס הודעות — הוא רק מחזיר הצעה או מעלה שגיאת ערך. הפונקציה מקבלת כעת `propose_rule(description, metadata)`.

## מטא־דאטה עסקי בבקשה

לצד `description` נדרש כעת `metadata`, באותו מבנה עסקי שמחזיר `GET /api/metadata` של הבקאנד: גרסה, ישויות עם שדות עסקיים, וקשרים כיווניים בין הישויות. `request.json` כולל צילום לדוגמה של המבנה הציבורי הקיים. הוא אינו מכיל `schema`, ‏`table`, ‏`column`, מפתחות SQL או מיפויים טכניים. במטא־דאטה מוגדר `extra="forbid"`, כך שתוספת שדות שלא הוגדרו במודל נדחית.

‏`metadata_validation.py` בודק שהישות והשדות בהצעה קיימים במטא־דאטה שנמסר, כולל שדה בצד ימין וניווט דרך מסלול קשרים. הבדיקה עוברת גם על ילדים בקבוצות מקוננות. חסר בשדה או בקשר הדרושים לדוגמת ה־Mock מחזיר שגיאה מפורשת, ולא הצעה חלקית. זו בדיקת הפניות בסיסית בלבד; התאמת סוגי השדות והקבועים, ייחודיות מזהים ותקינות הקטלוג נשארות לאימות המלא בבקאנד. ה־Mock משתמש עדיין בדוגמאות מוכנות ואינו מייצר לוגיקה חדשה מהמטא־דאטה.

## שירות HTTP מקומי

מתוך תיקיית הפרויקט הראשית:

```powershell
.\python-ai\.venv\Scripts\python.exe -m uvicorn api:app --app-dir python-ai --host 127.0.0.1 --port 8000
```

פתחו `http://127.0.0.1:8000/docs`, הרחיבו `POST /proposals`, לחצו `Try it out`, הדביקו את כל תוכן `request.json` (תיאור ומטא־דאטה) ולחצו `Execute`. הדוגמה האוטומטית של Swagger אינה קטלוג אמיתי; השתמשו בקובץ הדוגמה. תשובת 200 מכילה את הגדרת הבקרה כ־JSON. לעצירה לחצו `Ctrl+C` בטרמינל.

`api.py` מגדיר את הכתובת ומשתמש במודלים שב־`models.py`. מודל הקלט `ProposalRequest` בודק שהתיאור הוא טקסט באורך 1–2,000 תווים ושקיים מטא־דאטה במבנה הנדרש. קלט במבנה שגוי מחזיר 422; תיאור ריק מרווחים בלבד, בקשה שאינה נתמכת ב־Mock או שדה נדרש שאינו זמין מחזירים 400 עם `detail`. השירות אינו קורא או מעדכן את `request.json` או את `proposal.json`, אינו שומר בקרה ואינו מריץ אותה.

‏מודל התשובה `RuleProposal` מחייב שם, מזהה ישות ותנאי מסוג `RuleCondition`. התיאור אופציונלי ויכול להיות חסר או `null`. תנאי יכול להיות השוואה (`ComparisonCondition`) או קבוצה (`GroupCondition`), לפי `kind`. השוואה מחייבת שדה שמאלי ואופרטור; צד ימני נדרש מלבד בבדיקות `isNull` ו־`isNotNull`. הצד הימני הוא `FieldOperand` (שדה אחר) או `ConstantOperand` (ערך קבוע). קבוצה מחייבת אופרטור `and` או `or` ורשימת ילדים שאינם ריקים. כל ילד יכול להיות השוואה או קבוצה נוספת. העץ כולו מוגבל ל־100 צמתים ולעומק של 8 רמות, כולל התנאי הראשי, בהתאם לבקאנד.

‏ה־Mock מייצר כעת שתי השוואות פשוטות, שתי קבוצות AND וקבוצת OR. המודלים תומכים גם בקבוצות מקוננות, אך עדיין אין נוסח בקשה שמייצר קינון. המודל תומך בכל שמונת אופרטורי המנוע: `equals`, ‏`notEquals`, ‏`lessThan`, ‏`lessThanOrEqual`, ‏`greaterThan`, ‏`greaterThanOrEqual`, ‏`isNull` ו־`isNotNull`.

`ComparisonCondition.validate_right` הוא validator שרץ לאחר בניית מודל ההשוואה. הוא מוודא ש־`isNull` ו־`isNotNull` אינם כוללים צד ימין שאינו null, ולשאר ההשוואות יש צד ימין. ערך קבוע null אינו מותר בהשוואה רגילה. כך נשמרת הסמנטיקה הקיימת של הבקאנד.

`FieldReference` כולל `relationshipPath` אופציונלי — רשימת מזהי קשרים, עד ארבעה. כשהוא חסר או `null`, השדה שייך לישות השורש. לדוגמה, `isActive` ללא מסלול הוא פעילות העובד; עם `relationshipPath: ["employeeDepartment"]` הוא פעילות המחלקה. `response_model_exclude_unset=True` משאיר שדות אופציונליים שלא סופקו מחוץ לפלט. המודל בודק את מבנה המסלול ואורכו, אך לא את קיומו בקטלוג. עובד ללא מחלקה אינו מסומן על ידי השוואת פעילות המחלקה ל־false: ערך חסר שונה מ־false, לפי סמנטיקת המנוע הקיים.

המודל מוגדר באמצעות `response_model`, ולכן FastAPI בודק את הפלט ומציג את מבנה התשובה בתיעוד. פלט שאינו תואם למודל הוא תקלה בשירות (500), ולא שגיאת קלט של המשתמשת. התאמת מזהי השדות והקשרים למטא־דאטה נבדקת בנפרד ב־`metadata_validation.py`; התאמת סוג הערך לסוג השדה עדיין אינה מאומתת כאן. האימות המלא של הבקרה נשאר באחריות הבקאנד בעת החיבור.

החוזה כולל כעת תיאור ומטא־דאטה עסקי. בצד ‎.NET נוספה מחלקת `PythonAiRuleProposalProvider` מאחורי `IAiRuleProposalProvider`. היא שולחת תיאור ומטא־דאטה ציבורי מהקטלוג שבשרת, קוראת את התשובה כ־`RuleDefinition` ומעבירה אותה ל־`RuleValidator` הקיים. הכתובת מוגדרת ב־`AiService:BaseUrl` וזמן ההמתנה מוגבל ל־15 שניות. ה־endpoint ‏`POST /api/ai/proposals` מפעיל אותה ומחזיר רק הצעה תקינה, ללא שמירה או הרצה. הוא מקבל תיאור בלבד ומצרף בעצמו את המטא־דאטה. קלט לא תקין, תשובה פגומה, שירות לא זמין ו־timeout מטופלים בהודעות בעברית. הממשק כולל יצירה בעזרת AI, סקירה ועריכה בעורך המשותף ואישור מפורש לפני שמירה או הרצה; האישור מתאפס לאחר שינוי. פרטי הפעלה ובדיקות ב־`docs/AI_SERVICE.md`.

בדיקת מחלקת החיבור: `dotnet run --project backend/tests/AiProposalChecks` מתוך שורש הפרויקט. הבדיקה משתמשת בתשובות HTTP מדומות ואינה דורשת SQL Server או שרת פייתון פעיל. נבדקים גוף בקשה ללא מיפויי SQL, פענוח התנאים, אימות באמצעות המנוע הקיים, תשובה פגומה או null, שגיאת HTTP וביטול בקשה. בדיקת HTTP חיה ונפרדת נמצאת ב־`backend/tests/check_ai_integration.py`; הוראות ב־`docs/AI_SERVICE.md`.

## ‏בדיקות התאימות

‏כל המודלים דוחים שדות לא מוכרים והמרות טיפוסים אוטומטיות. קבועים שומרים על טיפוס ה־JSON שלהם; מספרים שאינם סופיים נדחים. מגבלות אורך השם והתיאור נמדדות לפי UTF-16, כמו ב־‎.NET. מזהי ישויות, שדות וקשרים נבדקים ללא הבחנה בין אותיות גדולות לקטנות. האימות העסקי המלא, כולל התאמת טיפוסי השדות והקבועים, נשאר ב־`RuleValidator`.

‏הקובץ `backend/tests/fixtures/rule-contract.json` כולל 39 מקרי תאימות שמשמשים את שתי השפות. הבדיקות אינן דורשות DB:

```powershell
.\python-ai\.venv\Scripts\python.exe -B -m unittest discover -s python-ai -p "test_*.py"
dotnet run --project backend/tests/AiProposalChecks
```

## הרצה באמצעות קבצים

מתוך תיקיית הפרויקט הראשית, יוצרים פעם אחת סביבה וירטואלית ללא חבילות:

```powershell
python -m venv --without-pip python-ai/.venv
```

מריצים את הקובץ באמצעות הפייתון של הסביבה:

```powershell
.\python-ai\.venv\Scripts\python.exe -X utf8 .\python-ai\main.py
```

`-X utf8` מגדיר קידוד UTF-8 כדי לתמוך בפלט בעברית. אין צורך להפעיל את הסביבה באמצעות Activate.ps1 כאשר משתמשים ישירות בנתיב של python.exe.

התיאור נקרא מהשדה `description` בקובץ `request.json`. אפשר להחליף בין הנוסחים הנתמכים בעורך ולהריץ שוב כדי לקבל את הבקרה המתאימה.

התוכנית בודקת שהקלט הוא אובייקט JSON עם תיאור מסוג טקסט שאינו ריק. קובץ חסר, שגיאת קריאה או קידוד, JSON לא תקין ותיאור שגוי מחזירים הודעה באנגלית וקוד יציאה 1. הצלחה מחזירה קוד 0. בקלט שגוי לא נוצרת הצעה חדשה; קובץ פלט מהרצה קודמת עשוי להישאר, והתוכנית מתריעה על כך. טיפול בשגיאת כתיבה של הפלט עדיין אינו כלול בצעד זה.

ההצעה נשמרת ב־`proposal.json` בקידוד UTF-8. פתחו את הקובץ בעורך כדי לקרוא את העברית; הודעת הטרמינל באנגלית כדי להימנע מתצוגה הפוכה. הקובץ נוצר מחדש בכל הרצה ואינו נשלח ל־Git.

תיקיית `.venv` היא מקומית, אינה נשלחת ל־Git וניתנת ליצירה מחדש. הותקנו בה pip, FastAPI ו־Uvicorn והתלויות שלהן, באישור המשתמשת. גרסאות החבילות נשמרו ב־`requirements.txt`.

לשחזור החבילות לאחר יצירת סביבה חדשה, מתוך תיקיית הפרויקט הראשית:

```powershell
.\python-ai\.venv\Scripts\python.exe -m ensurepip
.\python-ai\.venv\Scripts\python.exe -m pip install -r python-ai/requirements.txt
```
