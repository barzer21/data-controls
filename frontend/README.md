# Data Controls — Angular frontend

ממשק בעברית וב־RTL: רשימת בקרות שמורות עם דפדוף דרך השרת, עורך יצירה/עריכה בחלון קופץ ועמוד תוצאות ייעודי למחשב. לחיצה על „הרץ בקרה” מציגה את התנאים שהורצו מעל טבלת החריגות. סיכום הבקרה וכותרות הטבלה נשארים גלויים בגלילה.

קובצי העיצוב כתובים ב־SCSS, כולל העיצוב הגלובלי. זו גם ברירת המחדל ליצירת רכיבים חדשים באמצעות Angular CLI.

## הרצה מקומית

נדרשים Node.js בטווח `^22.22.3 || ^24.15.0 || ^26.0.0` ו־npm. הוראות הקמת הדאטה בייס נמצאות ב־[README הראשי](../README.md).

בטרמינל ראשון, משורש הפרויקט:

```powershell
dotnet run --project backend/DataControls.Api --launch-profile http
```

בטרמינל נוסף, מתיקייה זו:

```powershell
npm.cmd ci
npm.cmd start
```

פתחו `http://localhost:4200`. קובץ `proxy.conf.json` מעביר בקשות `/api/**` לשרת המקומי בפורט 5037. אחרי שינויו יש להפעיל מחדש את שרת Angular. ה־proxy משמש לפיתוח בלבד; בפריסה נדרש ניתוב API מתאים.

## מבנה ואחריות

רכיבי הממשק משתמשים בהפרדת קבצים אחידה: `component.ts` ללוגיקה, `component.html` לתצוגה ו־`component.scss` לעיצוב. ה־TypeScript מפנה אליהם באמצעות `templateUrl` ו־`styleUrl`. קובצי `component.spec.ts` מכילים את הבדיקות.

- `src/app/core/api`: מודלים ושירותי תקשורת לבקרות, מטא־דאטה והצעות AI.
- `src/app/core/routing`: אימות עמוד הרשימה וחזרה לספרייה אחרי שמירה, עם הודעת הצלחה וגלילה לראש העמוד.
- `src/app/features/rules/saved-rules-page`: תיאום הבקשות ומצב המסך באמצעות signals ו־RxJS.
- `src/app/features/rules/saved-rules-list`: הצגת שם, תיאור וסוג נתונים לפי המטא־דאטה, ללא קריאות HTTP.
- `src/app/shared/pagination`: רכיב דפדוף המקבל נתוני עמוד ומחזיר אירוע מעבר.

אין יצירת נתוני דוגמה אוטומטית. בקרות שנשמרו דרך ה־API יופיעו ברשימה; דאטה בייס ללא בקרות יציג הודעה מתאימה.

- `/rules?page=2`: עמוד הבקרות השני. „הרץ בקרה” פותח את `/rules/{id}/results?page=2`; חזרה לרשימה מחזירה לאותו עמוד.
- `shared/rule-condition`: תצוגה רקורסיבית של תנאי AND/OR לפי מטא־דאטה עסקי.
- `shared/execution-results`: טבלת תוצאות לפי `columns` מהשרת, ספירה וסיבות לחריגה.
- ההרצה מקבלת עותק של ההגדרה השמורה שנטענה ומוצגת. היא אינה שומרת או משנה את הבקרה.
- „יצירת בקרה חדשה” בסרגל הצד פותחת את `/rules/new`. „עריכה” פותחת את `/rules/{id}/edit`. שני המסכים משתמשים ב־`features/rules/rule-editor`, עם ההגדרה המלאה ומעבר בין עריכה להצגת הבקרה. אין חלונות קופצים.
- „יצירת בקרה בעזרת AI” פותחת את `/rules/ai/new`: הרכיב `ai-rule-creator` מקבל תיאור, וההצעה מוצגת בעורך המשותף לאישור מפורש. שינוי ההצעה מאפס את האישור.
- `shared/condition-editor`: עורך תנאים רקורסיבי לפי המטא־דאטה. ניתן לשלב קבוצות „וגם”/„או”, בדיקות חוסר, ערכים מוקלדים והשוואות בין שדות מאותו סוג, כולל קשרים עסקיים.
- „שמירה” ו„הרצה” הן פעולות נפרדות, ושתיהן משתמשות באימות השרת. תוצאות טיוטה מוצגות בתוך העמוד עם חיפוש וסינון; שינוי נוסף בטיוטה מנקה תוצאה קודמת ומבטל בקשת סינון פעילה.
- החלפת נתונים דורשת אישור לאיפוס התנאים. עזיבה עם שינויים שלא נשמרו דורשת אישור בתוך העמוד; בזמן בקשה הכפתורים מושבתים. לאחר יצירה מוצג העמוד האחרון ברשימה, ולאחר עריכה חוזרים לעמוד הקודם. לאחר שמירה מוצלחת מוצגת הודעת הצלחה; בכישלון הטיוטה נשארת והשגיאה מקבלת מיקוד. רענון וסגירת לשונית אינם מציגים אזהרה ואינם משמרים טיוטה.
- בעמוד התוצאות הייעודי יש חיפוש בשדות טקסט, ואייקון סינון בכותרות עמודות הנתונים. ניתן לסנן לפי ערך, תאריך, מספר, כן/לא או חוסר ערך; מסננים שונים מתחברים ב„וגם”. מסנני טקסט בעמודה משתמשים בהתאמה מדויקת; לחיפוש חלק מטקסט משתמשים בשורת החיפוש.
- החיפוש והמסננים נשלחים לשרת כאפשרויות הרצה זמניות. הם אינם משנים את הבקרה או את הסיבה לחריגה. אפשר להסיר מסנן בודד או ללחוץ „נקה הכל”; גם באפס התאמות הפקדים נשארים זמינים. מזהה הרשומה והסיבה המחושבת אינם נתמכים כשדות סינון ב־API הנוכחי.
- בשלב זה מוחזרות עד 100 רשומות עם הודעה כשיש תוצאות נוספות. הספירה מתייחסת לכל החריגות התואמות לחיפוש ולסינון, גם מעבר ל־100 הרשומות המוצגות. דפדוף בתוצאות ומחיקה יתווספו בנפרד.

לאחר התקנת תלויות חדשות (כולל Router) יש להפעיל מחדש את `npm.cmd start`. בפריסה יש להגדיר fallback ל־`index.html` עבור נתיבי Angular ולהשאיר את `/api` מנותב לבקאנד.

## בדיקות ובנייה

```powershell
npm.cmd test -- --watch=false
npm.cmd run build
```

הבדיקות משתמשות בשרת HTTP מדומה ואינן דורשות SQL Server. פלט הבנייה נוצר ב־`dist/data-controls/browser`.
